# Mini Booking

Локальное демо для оценки тестового задания: бронирование одной офисной переговорной. Каждый день, включая выходные, доступны девять часовых слотов с 09:00 до 18:00. Интерфейс и JSON API обслуживаются одним приложением Laravel.

## Зависимости

- PHP 8.2+ с расширениями Laravel и PHPUnit, включая `pdo_sqlite`, `mbstring`, `dom` и `xml`.
- SQLite 3.35+ (для `INSERT … RETURNING`), Composer 2.
- Node.js 22.12+ или 20.19+ в ветке 20, npm.
- Laravel 12, Vue 3, Vite и PrimeVue устанавливаются из файлов блокировки.

## Локальный запуск

Из корня репозитория:

```sh
composer install
npm ci
php -r "file_exists('.env') || copy('.env.example', '.env');"
php artisan key:generate
php -r "file_exists('database/database.sqlite') || touch('database/database.sqlite');"
php artisan migrate --seed
```

По умолчанию используются `DB_CONNECTION=sqlite`, файл `database/database.sqlite` и `APP_TIMEZONE=Europe/Moscow`. Для другой базы SQLite укажите путь к существующему файлу в `DB_DATABASE`. Часовой пояс задайте перед первым заполнением базы: повторный запуск сидера не пересчитывает ранее созданные слоты.

В двух терминалах:

```sh
php artisan serve --host=127.0.0.1 --port=8000
```

```sh
npm run dev
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Чтобы запускать приложение без процесса Vite, один раз выполните `npm run build` и оставьте запущенным Laravel.

`php artisan db:seed` добавляет недостающие слоты на семь календарных дней, считая сегодняшний день, и сохраняет прежние слоты и брони. Запускайте сидер вручную, когда нужно продлить расписание.

## API

| Запрос | Успешный ответ | Ошибки по условиям задачи |
| --- | --- | --- |
| `GET /api/slots` | `200`, массив слотов с полями `id`, `starts_at`, `ends_at`, `status`, `booking_id` | — |
| `POST /api/bookings` | `201`, объект с `id` | `422` с `errors` по полям; `409` с `message`, если слот занят или уже начался |
| `DELETE /api/bookings/{id}` | `204` без тела | `404`, если брони уже нет |

POST принимает JSON с `slot_id`, `customer_name`, `customer_email`. Слоты отсортированы по началу; значения статуса — `available`, `booked`, `past`. В списке слотов нет имени и email. `booking_id` равен `null`, если брони нет. В этом локальном демо любая бронь удаляется по известному ID; удаление освобождает будущий слот.

## Уникальность и время

- `bookings.slot_id` — внешний ключ и уникальный индекс. Запись выполняет один `INSERT … SELECT … RETURNING`: он проверяет, что слот ещё не начался, и сразу пытается занять его. Нет отдельной транзакции, которая сначала удерживает блокировку чтения и затем пытается переключиться на запись. SQLite ждёт освобождения записи до 5 секунд. Если две заявки пришли на один свободный слот, одна вставит запись, а другая получит `409` за нарушение уникальности `bookings.slot_id`. Остальные сбои БД обрабатываются как серверные ошибки.
- Сидер строит расписание в `APP_TIMEZONE` и записывает время в UTC. Слот считается прошедшим, если его начало совпало с текущим временем сервера или уже прошло. API возвращает ISO 8601 со смещением пояса расписания. Интерфейс берёт календарную дату и часы из ответа, поэтому часовой пояс браузера не влияет на показанное время.

## Проверки

```sh
php artisan test
php vendor/bin/pint --test
npm run build
```

Два теста PHPUnit работают с отдельной SQLite в памяти: успешная бронь будущего слота и отказ при повторной заявке с проверкой числа записей.

Отдельно два параллельных POST к одному слоту проверены на файловой SQLite с несколькими HTTP-воркерами: один ответ `201`, один `409`, одна активная бронь.
